## Objective and boundaries
Deliver a distinctive outdoor PvE destination reached by a dedicated rift, an optional safe expedition outpost, monumental Foundry entrance, four differentiated interior encounter areas, and a repeatable rare armor blueprint-to-fabrication loop. Preserve Phase Annex, existing characters, accounts, quests, companions and economy. No level-cap increase, new class, mandatory raid, PvP, auction house or player trading prerequisite. Existing active classes only. AO Temple of Three Winds informs pacing and location identity, not copied assets, maps or protected designs. Owner reference sheets guide original entrance and shelter production. WoW/Ashes of Creation are aspirational art references, not acceptance claims.

## Delivery governance
Re-fetch main, open PRs, branch heads, AGENTS and actual relevant code before starting or mutating. Resolve integration overlap with PR #115 (playtest coherence), #116 (electrical rod), #119 (armor foundation), and any entrance/asset work; identifiers are historical pointers, not assertions of current state. No competing edits to active branches without coordination. Use one focused topic per PR, stagger independent work; do not hold unrelated ready changes hostage to blocked dependencies. The umbrella branch is a register, not an excuse for an oversized integration PR. Content expansion promotion depends on canonical coherence gate. Prototype work may proceed on isolated branches when safe. No force push, blind retries, weakened tests or unverified PASS. Owner approval for routine delivery applies only when exact current candidate and applicable integration checks pass, material concerns resolved. Keep private odds, unreleased content, raw reference files and encounter scripts out of public Git; server-only is not confidential in a public repo. If private storage unavailable, defer sensitive implementation and continue independent work.

## Gameplay and world contracts
Travel: existing world -> dedicated rift -> outdoor safe arrival -> optional outpost -> Foundry doorway -> interior -> exterior -> return rift. Server determines destination and valid source/nearby interaction, rejects spoofed locations, tracks current zone through snapshots and storage. No implied automatic party teleport; document actual supported policy. Death, disconnect, restart, invalid legacy coordinates and unavailable instance must lead to safe documented recovery. Companions, combat targets, corpses, projectiles, party visibility and chat/map scope must follow actual zone boundaries. Keep player movement, camera, collision and server simulation consistent.
Environment: recognizable entrance visible from approach, non-linear traversal, no mandatory vendor purchase, outdoor content and resource gathering independently useful. Camp safe without providing instant exploit reset. Four interior themes are architectural and ecological distinctions, not simply palette swaps. Named encounters optional until balanced; no hard class lock for receiving blueprints.
Vendor: use existing inventory/wallet and service protocols; no client-supplied price/health value, positive bounded quantities, insufficient-credit/capacity failures without mutation. Healing self-use first; define cooldown persistence and full-health behavior before implementation; over-time effects, if added, must have cancellation/death/reconnect policy. No real-money mechanics.
Armor: class sets are coordinated with armor branch. Grant recipes rather than assembled pieces from relevant enemies. Learned recipes persist, duplicate outcome intentional, player-visible requirements explain discovery without revealing hidden pools. Keep trading optional/future, not required for completing sets. Existing profession XP rules reused, no competing engine. All numbers provisional until balance evidence.
Art: follow existing proven asset stages where relevant: reference ingest/provenance; authored geometry; topology/UVs; texture/materials; rig only for moving assets; export/validate; LOD and collision; real scene integration; capture and profile. Concept sheets are not sufficient input for reliable photogrammetry. Reuse compatible entrance and asset tooling; avoid copied AO assets. Inspect texture seams, shading, normals, scale and silhouettes. Avoid excessive glow and placeholder mannequin/primitive claims. Set measurable budgets based on existing measured baseline before production; no invented performance results.

## Verification matrix
- Unit: zone/transition rules, safe zone, range, eligibility, quantity arithmetic, cooldown, bounded healing, loot/recipe learning, persistence sanitization, set effects and resource cleanup.
- Integration: server travel lifecycle with restart/reconnect/death; two clients in same and separate zones; forged/cross-zone attacks, purchases, use, loot and gathering; concurrent requests and duplicate grants; failed mutations unchanged; companion and corpse lifecycle.
- Browser: actual input from existing world through rift to camp, buy/use heal on each active class, enter/exit Foundry, combat/loot, discover blueprint using deterministic test fixture (not live guaranteed drop), craft/equip, see authoritative stat changes, reconnect and return; verify existing Phase Annex and normal vendors.
- Asset: GLB integrity/import, materials, rig/animation where applicable, UV/texture quality, collision and camera clearance, LOD actually used, scene screenshots/video, no missing dependencies, provenance.
- Performance: compare representative scene against measured baseline on declared device/browser, record frame time, draw calls, triangles, texture memory estimate, load time, network and server tick behavior under representative population; investigate regressions, record limits.
- Balance: actual solo and small-party encounters across active classes, survivability, healing affordability, reward pacing, resource sinks and repeat visitation; test harness distributions privately, no public exact odds.
- Release: CI exact candidate and reconciled main, inspect actual jobs, no cancelled/skipped required checks treated as pass, no visual acceptance inferred from tests. Record SHA, PR, runs, captures and unresolved limitations. Roll back using reversible changes/compatible migrations; preserve saves, never destructively reset player data.

## Risk and decisions
High: location/persistence corruption, cross-zone interaction, duplicate economy grants, branch overlap, public disclosure, asset rights, performance and content scope. Mitigate with isolated contracts, server validation, migration fixtures, atomic transactions, branch ownership, private storage, provenance and measured budgets. Medium: camp exploit, class imbalance, indistinguishable zones, clipping and empty terrain. Mitigate with lifecycle tests and representative play/capture. Decisions deferred pending inspection: exact topology/size, population, shared vs instanced dungeon, progression entry policy, consumable values/prices, enemy balance, acquisition probabilities, hardware budgets and asset format details. Do not invent owner decisions; routine reversible implementation choices may proceed with documented rationale.
