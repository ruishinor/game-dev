# Engineering extraction: open-source WoW browser clients → Attunement

A decision aid, not a survey. Every row cites source that was actually read at
the commit shown. Nothing here imports Blizzard formats, data or assets: the
projects below ship code only, and Attunement uses ordinary GLB/glTF.

Not inspected: TrinityCore and vMaNGOS. They were named as secondary
references; AzerothCore's grid code answered the one server-side question
(interest management) and nothing from any emulator is being adopted, so
reading two more implementations of the same design was not justified.

No code was copied from any of these projects. Every adoption below is a
re-implementation of a technique in Attunement's own modules, so no third-party
licence notice is required.

## What changed in the renderer plan as a result

- Keep Three.js, `main.js`'s structure and the authoritative server untouched.
- Replace per-entity procedural meshes with shared GLB instances (rows 2, 3, 17).
- Replace scalar-driven limb rotation with a small prioritised animation
  controller on the native mixer (rows 6–9).
- Solve foreground obstruction by fading, not by camera tricks (rows 13–14).
- Do not build streaming, spatial cells, LOD chains, KTX2 or interest
  management yet (rows 5, 11, 12, 18); the manifest keeps those doors open.
